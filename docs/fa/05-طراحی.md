# طراحی و رابط کاربری

> **محدودهٔ این سند:** این یک **ارزیابی** است با یک اصلاح هدفمند، نه یک بازطراحی. هیچ صفحه‌ای
> بازنویسی نشد. دلیلش در بخش ۵ آمده.

---

## ۱. چیزهایی که از قبل درست بودند

این را باید صریح گفت، چون فرض اولیه این بود که رابط کاربری «تولیدشدهٔ هوش مصنوعی و سطحی» است:

| مورد | وضعیت |
| --- | --- |
| **راست‌به‌چپ** | **ساختاری است، نه وصله‌ای.** کد از خصوصیات منطقی CSS استفاده می‌کند (`ms-`, `me-`, `ps-`, `pe-`, `margin-inline`, `text-align:start`). فقط حدود ۲۰ مورد جهت فیزیکی در ۷۴ فایل باقی مانده. هیچ فایل جداگانه‌ای برای RTL وجود ندارد |
| **متن ترکیبی فارسی/انگلیسی** | کلاس `.latin` با `unicode-bidi:isolate` وجود دارد و روی نام‌های لاتین داخل متن فارسی اعمال می‌شود — مشکل «نشت جهت» از قبل حل شده |
| **فونت بر اساس زبان** | وزیرمتن برای فارسی، Inter برای انگلیسی، سوئیچ روی `html[lang]` |
| **نشانگر فوکوس** | یک `:focus-visible` سراسری تعریف شده — نه اشتباه رایج `outline:none` |
| **اندازهٔ لمسی** | آیتم‌های ناوبری `min-height:44px` |

**نتیجه:** پایهٔ راست‌به‌چپ و دوزبانه سالم است. مشکل جای دیگری است.

---

## ۲. مشکل واقعی: دو سیستم رنگ موازی

در `globals.css` **دو واژگان رنگی مستقل** تعریف شده‌اند که هر دو یک چیز را توصیف می‌کنند:

| مفهوم | سیستم الف | سیستم ب |
| --- | --- | --- |
| متن اصلی | `--navy: #121a42` | `--color-text: #111827` |
| کارت | `--surface: #fff` | `--color-card: #fff` |
| خط جداکننده | `--line: #e5e8f1` | `--color-border: #e6eaf2` |
| پس‌زمینه | `--canvas: #f8f9fd` | `--color-background: #f7f8fc` |
| موفقیت | `--green: #26a66f` | `--color-success: #16a34a` |

دقت کنید: مقادیر **نزدیک‌اند ولی برابر نیستند**. `#e5e8f1` در برابر `#e6eaf2`. هیچ‌جا نوشته
نشده کدام را باید استفاده کرد، پس هر کامپوننت یکی را انتخاب کرده و همان مفهوم بصری، در دو صفحهٔ
کنار هم، با دو رنگ کمی متفاوت رندر می‌شود.

### و ۱۶۳ رنگ دستی

- **۸۳** رنگ خام در خودِ `globals.css`، **بعد از** بلوک توکن‌ها
- **۸۰** رنگ خام مستقیماً داخل فایل‌های کامپوننت

یعنی توکن‌ها اقلیت رنگ‌های واقعی محصول را کنترل می‌کنند. رنگ ستارهٔ امتیاز (`#f5a623`، ۸ بار) در
هیچ توکنی وجود ندارد.

### و هیچ مقیاسی برای فاصله و اندازهٔ متن نیست

جست‌وجو برای `--space*`، `--text*`، `--leading*`: **صفر نتیجه**. تنها توکن‌های غیررنگی، یک
`--radius-card` و یک `--shadow-card` است.

پس شعار «بعد از تعریف توکن‌ها، هیچ مقدار جادویی در کامپوننت نباشد» فعلاً **قابل اجرا نیست**؛
چیزی برای ارجاع‌دادن وجود ندارد.

## ۳. ایراد دسترس‌پذیری که پیدا و برطرف شد

توکن `--muted` (رنگ متن‌های فرعی: زیرنویس‌ها، توضیح قیمت، بیوگرافی مدرس) نسبت کنتراست
**۴٫۱۹:۱** داشت. استاندارد WCAG AA حداقل **۴٫۵:۱** می‌خواهد.

این توکن **۲۱۸ بار در ۴۵ فایل** استفاده می‌شود.

| ترکیب | نسبت | نتیجه |
| --- | --- | --- |
| `--muted #6f7890` روی `--canvas` | **۴٫۱۹:۱** | ❌ مردود |
| `--color-text-secondary #667085` | ۴٫۶۹:۱ | ✅ قبول |
| مقدار جدید `#5b6478` | ۵٫۵۹:۱ | ✅ قبول |

**برطرف شد** با تغییر یک خط — که هر ۲۱۸ استفاده را یکجا اصلاح می‌کند.

> **نکتهٔ مهم:** این نشان می‌دهد دو سیستم موازی، مشکل ظاهری نیست. از میان دو توکن هم‌معنی،
> **همانی که بیشتر استفاده می‌شود، همانی بود که مردود شد.**

> **تصحیح:** پیش‌نویس اول این سند ادعا کرده بود توکن دیگری (`--color-text-secondary`) مشکل دارد
> و عدد را «حدود ۴٫۴» زده بود. آن یک تخمین بود و هم در توکن و هم در عدد اشتباه بود. اعداد بالا
> **محاسبه‌شده‌اند**. این تصحیح عمداً حذف نشده: ادعای دسترس‌پذیری که فقط «محتمل» باشد، ارزشی
> ندارد.

## ۴. توکن‌های پیشنهادی (اجرا نشده)

یکپارچه‌سازی روی نام‌های **معنایی**. دلیل انتخاب سیستم ب: `--color-text` می‌گوید «برای چه
کاری است»، ولی `--navy` می‌گوید «چه شکلی است» — و همین باعث واگرایی می‌شود.

```css
:root{
  --color-bg:#f7f8fc; --color-surface:#fff;
  --color-text:#111827; --color-text-muted:#5b6478;
  --color-border:#e6eaf2; --color-primary:#4f46e5;
  --color-star:#f5a623;          /* قبلاً فقط عدد خام در ۸ کامپوننت بود */

  --space-1:.25rem; --space-2:.5rem; --space-4:1rem; --space-8:2rem;
  --text-sm:.875rem; --text-base:1rem; --text-xl:1.5rem;

  /* فارسی در یک اندازهٔ یکسان به ارتفاع خط بیشتری نیاز دارد.
     این مهم‌ترین تفاوت تایپوگرافیک بین دو زبان است و امروز
     هیچ‌جا بیان نشده. */
  --leading-body:1.9;
}
html[lang="en"]{ --leading-body:1.6; }
```

**ترتیب مهاجرت** (هر مرحله مستقلاً قابل انتشار):

۱. مقیاس بالا را **کنار** توکن‌های فعلی اضافه کنید — چیزی نمی‌شکند
۲. سیستم الف را به ب متصل کنید (`--navy: var(--color-text)`) تا دیگر نتوانند از هم دور شوند
۳. رنگ‌های دستی را **صفحه‌به‌صفحه** جایگزین کنید: صفحهٔ اصلی ← فهرست مدرسان ← پروفایل مدرس ←
   پرداخت ← نتیجهٔ پرداخت
۴. وقتی هیچ ارجاعی نماند، سیستم الف را حذف کنید

## ۵. چرا صفحات بازطراحی نشدند

سه دلیل:

۱. **قواعد خود ممیزی، بازسازی ناخواسته را ممنوع می‌کند.** بازنویسی دوازده صفحه یک پروژه است،
   نه یک قدم از ممیزی.
۲. **مشکل، ظاهر صفحات نیست.** مشکل این است که **منبع حقیقت واحدی برای طراحی وجود ندارد**. تا
   وقتی دو سیستم توکن و ۱۶۳ رنگ دستی هست، هر صفحهٔ بازطراحی‌شده هم دوباره واگرا می‌شود.
۳. ترتیب درست این است: اول توکن‌ها، بعد صفحه‌ها.

## ۶. سیاههٔ دسترس‌پذیری

| بررسی | نتیجه |
| --- | --- |
| `lang` و `dir` درست در سطح سند | ✅ |
| نشانگر فوکوس دیده می‌شود | ✅ |
| خصوصیات منطقی (RTL ساختاری) | ✅ |
| جداسازی جهت در متن ترکیبی | ✅ |
| هدف لمسی ≥ ۴۴ پیکسل | ✅ برای ناوبری؛ کل کنترل‌ها بررسی نشد |
| برچسب فیلد متصل به خطا | 🟡 در فرم برداشت وجه تأیید شد؛ سراسری بررسی نشد |
| کنتراست ≥ ۴٫۵:۱ | ✅ بعد از اصلاح `--muted` |
| ناوبری با صفحه‌کلید | ❌ بررسی نشد |
| واکنش‌گرایی در ۳۶۰/۷۶۸/۱۰۲۴/۱۴۴۰ | ❌ بررسی نشد — هیچ ماتریس اسکرین‌شاتی تولید نشد |
| حالت‌های بارگذاری/خالی/خطا در همهٔ کامپوننت‌ها | ❌ بررسی نشد — ادعایی نمی‌کنیم |

سه مورد آخر **انجام نشده‌اند** و در [کارهای باقی‌مانده](07-کارهای-باقی‌مانده.md) ثبت شده‌اند.
