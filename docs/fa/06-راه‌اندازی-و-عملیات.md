# راه‌اندازی و عملیات

تمام دستورهای این سند **واقعاً اجرا شده‌اند** و کار می‌کنند.

---

## ۱. پیش‌نیازها

- **Node.js ۲۰ یا بالاتر** (آزمایش‌شده روی ۲۲٫۱۷٫۱)
- **Docker** با Compose (آزمایش‌شده روی ۲۹٫۵٫۲)
- **npm ۱۰+**

---

## ۲. راه‌اندازی از صفر

```bash
npm run setup        # کپی .env.example به .env و apps/api/.env در صورت نبود
npm run services:up  # postgres + redis + minio تا سالم‌شدن، و ساخت باکت
npm run db:prepare   # تولید کلاینت + اعتبارسنجی + مهاجرت + دادهٔ نمونه
npm run dev:api      # API روی localhost:4001
npm run dev          # وب روی localhost:3000
```

خروجی مورد انتظار `db:prepare`:

```
✔ Generated Prisma Client
11 migrations found in prisma/migrations
No pending migrations to apply.
```

بررسی سلامت:

```bash
curl http://localhost:4001/api/health
# {"status":"ok","database":"connected","cache":"connected"}
```

> ⚠️ **نکته:** API پیشوند `/api` دارد. آدرس `localhost:4001/health` خطای ۴۰۴ می‌دهد؛ آدرس درست
> `localhost:4001/api/health` است.

## ۳. متغیرهای محیطی

| متغیر | ضروری؟ | توضیح |
| --- | --- | --- |
| `DATABASE_URL` | بله | باید با `POSTGRES_*` در `.env` ریشه یکی باشد |
| `REDIS_URL` | بله | قفل، محدودیت نرخ، ابطال توکن |
| `JWT_ACCESS_SECRET` | بله | حداقل ۳۲ کاراکتر. «فلفل» کد یک‌بارمصرف هم از این ساخته می‌شود |
| `JWT_REFRESH_SECRET` | بله | حداقل ۳۲ کاراکتر |
| `S3_*` | بله | فایل‌ها (MinIO در توسعه) |
| `AUTH_DEV_OTP` | فقط توسعه | کد را روی `123456` ثابت می‌کند. **در تولید، برنامه بالا نمی‌آید اگر روشن باشد** |
| `TRUST_PROXY` | تولید | تعداد پراکسی‌های جلوی API. اگر اشتباه باشد، محدودیت نرخ بر اساس IP دقیق نیست |
| `KAVENEGAR_API_KEY` | تولید | باید **خط خدماتی** باشد نه تبلیغاتی، وگرنه کد به شماره‌های مسدودکنندهٔ تبلیغات نمی‌رسد |
| `ZARINPAL_MERCHANT_ID` | تولید | بدون آن، درگاه به حالت توسعه می‌افتد |
| `ZARINPAL_SANDBOX` | فقط توسعه | در تولید رد می‌شود |
| `NEXT_PUBLIC_ENAMAD_HTML` | تولید | نماد اعتماد. **در زمان بیلد درج می‌شود** — بعد از تنظیم، نیاز به بیلد مجدد دارد نه ری‌استارت |

```bash
npm run env:check   # بررسی وجود متغیرها، طول کلیدها و هم‌خوانی DATABASE_URL
```

> **اختلاف فعلی:** `.env` دو کلید `TRUST_PROXY` و `NEXT_PUBLIC_ENAMAD_HTML` را ندارد که در
> `.env.example` هستند. در توسعه مشکلی ایجاد نمی‌کند، ولی برای تولید باید تنظیم شوند.

## ۵. پشتیبان‌گیری

پایگاه داده تنها منبع حقیقت مالی است. دفتر کل کیف پول فقط‌افزودنی است، پس تاریخچه هرگز بازنویسی
نمی‌شود — ولی این جای پشتیبان را نمی‌گیرد.

```bash
docker compose exec postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup-$(date +%F).sql
```

**پشتیبانی که بازیابی‌اش آزمایش نشده، پشتیبان نیست.** ماهی یک بار روی یک پایگاه دادهٔ خالی
بازیابی کنید.

فایل‌های MinIO جداگانه پشتیبان می‌خواهند.

## ۶. کتابچهٔ رخداد: پرداخت‌های مشکل‌دار

### «پول کم شد ولی کلاس فعال نشد»

**اول بدانید: سیستم برای این حالت راه ترمیم خودکار دارد.** هر ۱۰ دقیقه، کار تطبیق مالی
پرداخت‌های بلاتکلیف را دوباره از زرین‌پال می‌پرسد و در صورت تأیید، خودش نهایی می‌کند.

۱. پرداخت را پیدا کنید:
   ```sql
   SELECT id, status, amount, authority, "gatewayReference", "createdAt"
   FROM "Payment" WHERE "userId" = '...' ORDER BY "createdAt" DESC LIMIT 5;
   ```
۲. اگر `PAID` است ولی رزرو `CONFIRMED` نیست → مشکل در مرحلهٔ فعال‌سازی است، نه پرداخت.
۳. اگر `PENDING` است و بیش از ۱۰ دقیقه گذشته → جدول `Reconciliation` را ببینید:
   ```sql
   SELECT * FROM "Reconciliation" WHERE "paymentId" = '...';
   ```
   وجود ردیف یعنی سیستم مغایرت را دیده است.
۴. **هرگز وضعیت پرداخت را دستی به `PAID` تغییر ندهید.** این کار دفتر کل و کارمزد مدرس را
   نمی‌سازد و حساب‌ها را ناهماهنگ می‌کند. بگذارید مسیر تطبیق کارش را بکند.

### «کاربر می‌گوید دو بار پول داده»

```sql
SELECT id, status, amount, "idempotencyKey", "createdAt"
FROM "Payment" WHERE "bookingId" = '...';
```

اگر دو ردیف `PAID` هست، بازپرداخت از پنل مدیریت انجام دهید — که حالا در برابر دابل‌کلیک هم امن
است.

### «کد ورود نمی‌رسد»

۱. `KAVENEGAR_API_KEY` تنظیم است؟ بدون آن API خطای ۵۰۳ می‌دهد (عمداً «بسته» شکست می‌خورد).
۲. کلید از **خط خدماتی** است؟ خط تبلیغاتی به شماره‌هایی که تبلیغات را مسدود کرده‌اند نمی‌رسد.
۳. قالب‌های `lingospeak-otp` در پنل کاوه‌نگار وجود دارند؟
۴. آیا کاربر به سقف خورده؟ ۵ بار در ساعت برای هر شماره، ۱۰ بار در ۱۰ دقیقه برای هر IP.
   پاسخ ۴۲۹ هدر `Retry-After` دارد.

### «همه چیز ۵۰۳ می‌دهد»

احتمالاً Redis قطع است. محدودیت نرخ عمداً **بسته** شکست می‌خورد تا مسیرهای حساس بی‌محافظ نمانند.

```bash
docker compose ps
docker compose logs redis --tail 50
```

نقش‌های مدیریتی هم در این حالت ۵۰۳ می‌گیرند (عمدی)، ولی کاربران عادی باید کار کنند.

## ۷. پایش (هنوز پیاده نشده)

آنچه **باید** پایش شود و امروز نمی‌شود:

- تعداد پرداخت‌های `PENDING` قدیمی‌تر از ۳۰ دقیقه (نشانهٔ خرابی تطبیق)
- هر ردیف جدید در `Reconciliation` با `matched = false`
- نرخ خطای ۵۰۳ (سلامت Redis)
- تعداد پیامک ارسالی در ساعت (هزینهٔ واقعی)
- هر پرداخت `PAID` بدون `gatewayReference`

هر درخواست یک `requestId` دارد که در پاسخ خطا هم برمی‌گردد — پایهٔ ردیابی موجود است، ولی ارسال
متمرکز لاگ راه‌اندازی نشده.
